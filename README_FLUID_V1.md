# FLUID V1 — The Abyssal Garden

A first cinematic environment slice: a submerged canyon, procedural bioluminescent gardens, suspended particulates and a fractured ancient ring. V1 contains environment art and navigation only.

## Open the environment

- Blender 5.1: `blender/scenes/FLUID_V1_Environment.blend`.
- Camera animation: frames 1–720 at 24 fps, lasting 30 seconds. Numpad 0 enters the camera view; use the timeline to inspect the route.
- Review stills: `renders/previews/`. The Blender movie is a 960×540, 12 fps review copy of the source animation; it is not the final delivery render.
- Unreal 5.8: open `/Game/FluidWorld/Maps/L_AbyssalGarden` in VidyaAdmireLab. Use Play for the native flying pawn. Mouse looks, WASD moves, E/Q moves vertically; Escape ends Play.
- Unreal camera sequence: `/Game/FluidWorld/Cinematics/LS_V1_Descent`, 30 seconds at 24 fps. Open in Sequencer and enable camera cuts to preview it. It does not autoplay during free navigation.

## Source organization

```text
blender/
  scenes/FLUID_V1_Environment.blend  Main assembled scene and cinematic
  assets/geology.blend              Reusable rock sources
  assets/vegetation.blend           Reusable coral, fans, kelp and trumpet forms
  assets/landmark.blend             Reusable ring and accent sources
  textures/                        Portable base-color PNGs
  scripts/                         Deterministic build, export and review scripts
exports/
  unreal/                          22 FBX assets plus placement/camera/light manifest
  webgpu/                          Reserved for a later version
renders/
  previews/                        Reviewed stills
  cinematics/                      Review movie
docs/                              Build measurements and validation evidence
```

The main scene uses local mesh data shared by instances. The asset-family files are reusable snapshots, not live-linked dependencies; changing one does not automatically update the main scene. Textures use relative paths. Keep the folder hierarchy together when moving it.

## Editing

- `01_ENVIRONMENT`: seafloor, placed geology, landmark and curated vegetation.
- `02_PROCEDURAL_SYSTEMS`: Geometry Nodes scattering systems; edit density and seed in their modifier inputs.
- `03_LIGHTING`: canopy, foreground, landmark and shaft lights.
- `04_ATMOSPHERE`: underwater volume and the 1,500-mote Geometry Nodes system.
- `05_CAMERAS`: animated descent camera and named timeline markers.
- `06_EXPORT_PROXIES`: reserved for later simplified representations.
- `90_ASSET_SOURCES`: hidden source collections for reusable families. Unhide to edit.

Five Geometry Nodes groups handle habitat scattering and particle instancing. Branches, kelp, fans, rocks and the landmark are generated by the deterministic Python builder. They are editable meshes; their generation rules live in the script. Asset generation is not entirely implemented in Geometry Nodes.

The Blender scene uses meters. Export calibration verifies Unreal centimeters and the Y-axis reversal. Unreal keeps 2,141 placements in 21 instanced mesh components rather than thousands of independent actors. The calibration mesh is an additional test asset, not a scene placement.

## Export and future versions

The FBX files preserve reusable meshes; `scene_manifest.json` preserves scene placement, camera samples and light descriptions. Blender Geometry Nodes graphs, volume shaders and compositor effects are not transferred into Unreal. Unreal materials, fog and lighting are recreated for the engine; identical pixels across renderers are not promised. Portable base-color textures are included; Blender's procedural micro-bump is not baked into normal maps in this slice.

Static Unreal terrain, rock and ring collision uses complex-as-simple geometry. Vegetation and particles are decorative and have no collision. This is a navigation implementation, not the future solver's obstacle representation. The native flying pawn supplies free movement, not buoyancy or underwater physics.

V2 should extend these source families and update the same map with creatures and independent base animation. V3/V4 can export runtime assets and add validated field/solver integration. No fluid solver, WebGPU code, creature logic or ScientificRenderer changes are included in V1.

## Rebuilding

Run Blender in background factory-startup mode with `build_fluid_v1.py -- --root <output-folder>`. Use a new output folder: the builder intentionally recreates its generated scene. Open that scene in background mode and run `export_fluid_v1.py -- --root <output-folder> --previews` to regenerate FBX placements and preview checks.

`import_fluid_unreal.py` builds `/Game/FluidWorld` in the isolated `FluidValidation.uproject` used for QA. Its guard prevents accidental rebuilds in an unrelated project. Reviewed assets are copied into the existing project only after validation. Runtime use does not require the Python editor plugin.

## Quality and limits

This is a stylized first vertical slice, not a claim of production-grade photorealism. Remaining art work includes richer rock micro-detail, less repeated plant silhouettes, more varied ground dressing, final material baking, broader exploration coverage and platform profiling. Camera/path clearance checks are sampled and do not prove every possible route is clear.

Measured Blender stills at 1440×810, 64 Cycles samples with GPU rendering took 6.18–7.00 seconds per reviewed view on this machine. These are offline render times, not real-time FPS. Build and gameplay evidence are recorded separately in `docs/`.
